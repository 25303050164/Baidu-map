## 结论

两个引擎都能从选点一路跑到报告，且报告里的四项证据出现在**同一轮**：总体与分类覆盖区间、
覆盖/缺口/未知面积、灰区面积与清单、模型网格采样。这一轮里没有"本次未进行服务覆盖评估"
的降级路径，也没有空几何。

- 可以成立的：核心模型链路（成圈 → 设施检索 → 服务覆盖与灰区 → 报告）跑通，核验阶段执行但未取得路线证据，
  两个算法各自给出自己的边界与结论，业务状态为 `partial`（`interior_not_independently_verified`、
  `budget_exhausted` 等质量标记如实带出），修订 5 版齐全。
- 不能成立的：这不是"设施目录已经查全"。`catalogCompleteness` 是 `unverified`，本次核验的
  4 处设施均未取得严格路线结论（`checked=4 / failed=4`，均为 `deadline`），灰区的含义始终是"模型判定在
  1000 米内没有该类设施"，不是"确定没有"。

### 核验（本轮未取得百度路线证据）

`baidu_direction`，`checked=4 / failed=4 / unresolved=0`：四条记录均为 `pending/deadline`，
`routeDistanceM`、`durationS`、`withinRule` 与实际端点均为空。核验适配器把剩余秒数误当成
单调时钟绝对截止时间，Provider 在发 HTTP 前就退出。`failed` 是没有严格结论的数量，
不是超标准数量。归档中的 `endpointVerified=true` 同样是失败观测的默认值误报。
因此本轮既没有已证实可达样本，也没有已证实超标准样本。

### 成圈算法自己标出的不确定区（§6.1）

```

osm_hybrid  engine_unknown_region_m2=1642562.34
```

两个数都只是被**报出来**让人看见，没有从评估域里扣除：hybrid 标出的不确定区（164 万 m²）比

## 本轮发现并修复的问题

真实验收的价值就在这里 —— 以下 5 处都是**只有真链路才会暴露**的，离线套件此前全绿：

1. **导入 app 对象会杀掉正在跑的体检。** `tools/export_contract.py` 的 `from app.main import app`
   触发 `CheckupStore.initialize()` 的重启清点，于是导出 OpenAPI 顺手把一次真实体检判成
   `interrupted_by_restart`（本次记录里 `7dd34c9a…` 就是这么死的：它当时正在 `isochrone` 阶段，
   而进程里刚跑过一次导出契约）。已把 `create_schema()` 与
   `interrupt_unfinished()` 拆开，清点只在服务启动的 lifespan 里做。
2. **评估域被成圈不确定区整块扣没。** 见上；分母 A 现在只由圈面和数据覆盖范围决定。
3. **成圈的尝试次数在组装时被吃掉。** `IsochroneSnapshot.build` 收下 `requests_used` /
   `network_requests` 却没传给构造器，两个引擎的 400 次成圈请求都记成 0；设施阶段发布时重写
   计数器，"本任务已用"里的数字会从 226 掉回 28，`trace.budgets.isochrone.spent` 恒为 0。
   两列本轮记录为 428 = 400 + 24 + 4，只增不减；复核发现末项 4 是发 HTTP 前的本地短路，
   不应称为 428 次已证实付费调用，也不能据此推断百度账单。成圈自己数的边界采样留在
   `snapshot.statistics` 里。Hybrid 适配器原来把本地行走查询也当网络请求计数，一并按 provider
   是否联网分开。
4. **报告里的提示行按 code 撞 React key。** 一次 hybrid 体检带回 5 条 `ALGORITHM_WARNING`，
   提示行与"算法质量标记"都拿 `code` 当 key，React 会丢一条或重复一条 —— 而这两块的意义正是
   "一条不少"。
5. **真实验收用例的单位断言永远不会成立。** 界面在一万平方米以上改用公顷，用例却断 `m²|km²`。

## 尚未成立的部分

- `catalogCompleteness=unverified`：查询状态只说明计划中的请求与空间范围跑完了，不代表现实中的
  设施都已被收录。灰区永远可能由目录缺失造成。
- 四个池的合计（428）超过等时圈档位（400）是正常的：档位只限成圈，设施、核验、详情各有自己的池；
  界面上已按两行分开表述；但本轮核验的 4 次不对应实际发送，不能将合计直接称为付费次数。
- 成圈仍按 §9.1 走旧共享闸门，其尝试不从这个账本扣；账本只覆盖本应用自己的额度。
- 核验只覆盖本次检索到的设施，且本轮 4 处均未取得路线，因此可达和超标准在本轮都没有实测样本。
- 覆盖与灰区来自 OSM 步行路网模型，不是实测步行时间；路网缺失处不插值，标为未知。
- 没有人口数据，不输出人口覆盖率，也不判断居民是否被服务。
