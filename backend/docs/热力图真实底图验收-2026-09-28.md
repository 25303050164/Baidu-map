## 判读方法

- **期望值独立计算，不从页面取。**
  - 服务覆盖：取评估格原文，按地面米（半正矢距离）重新求双权核权重，核半径 = 格边长，再做归一化加权平均。
  - 设施密度：按 `K(d) = 3/(πr²)·(1−d²/r²)²`，r = 120 米求解析和，单位换算到个/公顷。
  - 只借用源码里的两条色带（`densityRgba`、`distanceRgb` 及三态颜色常量），也就是"颜色的定义"。
    网格、投影、累加、裁剪这些被测代码一概不借。
- **读数位置由地图自己换算。** 先用 `map.pointToOverlayPixel` 得到覆盖物像素，减去画布的 `left/top`，
  再乘设备像素比取整后读像素。同一经纬度在平移、缩放、改窗口后读出同一颜色，即"不错位"。
- **只在读得准的地方判颜色。**
  - 服务覆盖：只判核半径（再放宽 15 米）内全是同一种结论的点，且该点离等时圈边和评估域边 ≥ 30 米。
  - 设施密度：离圈边 ≥ 8 米。
  - 圈外与孔洞只判透明。混合过渡带不判，不去猜两种颜色该混成什么样。
- **容差。**
  - RGB ±10，另加 ⌈128/alpha⌉：画布按预乘 alpha 存 8 位颜色，核尾巴上 alpha 只有十几时，读回误差可达 ±8。
  - alpha：服务 ±10，密度 ±12。
  - 密度点另允许 1.5 CSS 像素的定位误差：画布小数偏移会落整像素，探针再向下取整到设备像素。
    原位颜色不符时，按该点周围 1.5 像素内的解析密度区间判，米/像素在页面里实测。用到时记 `shifted`。
    本次只有一处用到（见合成设施表）。
- 离画布边不足 4 像素的点记 `null` 不计。每个视图另规定视口内至少要判多少个点。

## 本轮发现并修复的缺陷

**现象**：在真实 BMapGL 上把服务覆盖或设施密度热力关掉再打开，画布不再出现（0 张）。
假 SDK 上的单测与 e2e 都没有发现。

**原因**：BMapGL 的 `addOverlay` 经 `Overlay.prototype._i` 调用覆盖物。它只在覆盖物没有 `domElement` 时才调 `initialize`，并缓存返回的元素。
基类 `remove()` 会清空 `domElement`；我们的覆盖物覆写了 `remove()` 却没有清空。
于是第二次 `addOverlay` 直接跳过 `initialize`，画布不再创建。

**修复**：`src/map/layers/canvasOverlay.ts` 的 teardown 清空 `domElement`。
视图事件（moveend / zoomend / resize）改为先解绑再绑定，重复 initialize 不叠加监听。

**回归**：三个假 SDK 都改成与真实 SDK 相同的缓存语义，分别是
`heatmapOverlay.test.ts`、`serviceOverlay.test.ts` 里的假 API，以及 e2e 的 `tests/mapSdk.ts`。新增两条用例：

- `heatmapOverlay.test.ts`："关掉再打开（detach → attach）重建画布：SDK 缓存的 domElement 不会挡住 initialize"，
  连做 3 轮，并断言 moveend / zoomend / resize 各只有 1 个监听；
- `serviceOverlay.test.ts`："关掉再打开后画布重建并重画，不因 SDK 缓存的 domElement 而空白"。

两条都在去掉修复时失败、加上修复后通过。真实地图上的开关回归由上面生命周期用例的第 2 步覆盖。

## 剩余限制

- **孔洞样本少**：E8.2 唯一的真实孔只有 73 m²，是个被挤窄的三角形；OSM＋百度没有 ≥ 40 m² 的孔。
  大孔的挖空由单测 `扫描线按奇偶规则填充：孔洞不填` 等覆盖，真实地图上只验了这一个小孔。
- **没有真实的高密度样本**：这一处真实设施只有 4 家，密度颜色偏淡。高密度、饱和、重复合并用明确标注的合成设施验证，
  不代表任何真实地点。
- **综合模式未在真实地图上判读**：只判了单类（医疗）。综合模式的"覆盖类别占比"与"缺类即未知"只由单测覆盖。
- **障碍未单独判读**：两条任务都带障碍层（报告里 `obstacleLayerAvailable: true`），但判读点没有专门选在障碍附近。
  障碍对覆盖的影响只通过评估格结论与等时圈形状间接体现。
- **OSM＋百度的纯缺口点只有 1 个**：它的缺口格零散，满足"核内全是缺口"的位置只有一处。
- **v2 生命周期的真实地图验证只覆盖已完成任务**：创建中、运行中、取消中、失败、断网、过期由 v2 单测覆盖，
  旧版页面还有 integration 覆盖（均为模拟服务）。这几种状态没有在真 AK 下再跑，以免花额度。
- **过渡带不判**：结论交界处一个格宽的过渡带不做颜色判读，只保证它不越过相邻格中心（单测覆盖）。
- 服务覆盖始终是模型估计。严格可达以"核验设施"层与报告里的核验结论为准，
  09-27 复验时两任务的严格确认数都是 0。
