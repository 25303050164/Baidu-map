## 推荐后续实施顺序

1. 在有明确账户权限和测试预算后，以相同中心和 POI 做少量真实基线。分别记录 POI 搜索、walking、排队/冷却、重试、geometry、报告耗时；不记录凭据或带密钥 URL。当前模拟 QPS=3 不代表已经读取生产配置。
2. 审核后台进程与独立 B1 采集器的共同账户配额。保留当前到达节拍保证；不要仅改 Semaphore 数或移除 attempt_lock。若设计并发 limiter，需新的到达节拍、429/冷却、截止、取消、跨进程和重试加权测试。
3. 若真实场景存在重复 OD，先统计潜在缓存命中率。安全 cache 键需覆盖 provider/API版本/metric/坐标系/起终点/UID，定义有效期；无结果、瞬时失败、不同 UID 入口不能盲目复用。不能用暖缓存与冷基线制造收益。
4. 矩阵仅在业务证据等价问题解决后进入真实对照。其限制与来源见报告第 12 节；错误或无结果保持 unknown，不能拿矩阵数值设置 endpoint_verified。必须比较距离、端点与覆盖结论，评估补发单路验证的成本。
5. 继续采用现有采样数量、设施候选上限、完整性规则和距离阈值。N=50/100 应保持同样输入，至少三轮，并公布均值/min/max、请求/失败/重试和实际并发。有效 wall-clock 收益出现后再提正式代码 PR。

## 生产验收门槛

相同输入下 POI/类别/去重/可达及 unknown/错误/设施统计一致；没有新增真实服务限流；全局请求预算和取消回收正确；N=50/100 的 wall-clock 改善超过测量噪声，不能用 CPU 控制时间替代完整调用。具体合格改善幅度应在真实基线完成后约定，不在本轮虚构数值。
