# POI 批量距离矩阵接入建议

结论：**NO，当前不建议正式合入。** 详细依据见 [实验报告](POI批量距离矩阵实验报告.md) 和 [性能对照](matrix-comparison.csv)。本轮仅模拟网络 PoC，未声称真实 Provider 提速。

## 已证明与未证明

已证明本地适配可按官方格式分批、逐格保留 unknown、按 OD 计费并限制重试。3 OD/秒下最多改善 9.858%，仍是弱收益。假设 50 OD/秒且服务端并行时，纯数值传输最高改善 98.367%，但完整业务证据一致率为 0%；此速度不能当作生产成果。

未证明真实矩阵与 directionlite 的距离/时间及 UID 绑路等价；矩阵没有当前 50m 端点校验所需 steps，也没有路线 path。补发所有单点验证可保持 100% 证据一致，但 OD 翻倍且各规模更慢。批次失败还会增加健康 OD 的重复计费。

## 下一步

1. 先解决端点证据与选路 metric 的兼容性，不以矩阵 raw 数值直接标记可达或覆盖。若平台无可用等价证据，停止作为直接替代方案。
2. 在真实账户权限、OD QPS、日预算明确且服务可运行后，以少量相同 OD 做两 API 成对测量，不读取或输出真实 AK，不记录含凭据 URL。比较原始数值、实际端点证据、无结果与失败。
3. 记录分阶段真实耗时，确认是 walking、POI 搜索、等待还是重试占优；低配额下先量化安全缓存命中空间，禁止用热缓存对比冷基线。
4. 仅当业务正确性、失败率、平台限制和 N=50/100 wall-clock 收益同时通过，才设计新的正式 provider + OD 加权全局 limiter + 小批次/预算/取消/逐格隔离/受限回退。批次 50 只是高配额理想模拟中的容量最优，不能硬编码为生产配置。
