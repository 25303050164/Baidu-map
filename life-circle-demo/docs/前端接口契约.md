# 前端实际使用的接口契约

核对基线：2026-09-13，`main` / `7d86f07`；本文同时记录 Round 3 的前端等待、错误和结果保留行为。依据是当前源码；设施模块为有限检索与采样点核验（见第 8 节），不代表全量目录。

## 1. 入口与配置

`src/main.tsx` 默认加载 `analysis/ApiApp.tsx`，经 `AnalysisController` → `createApiService` → 后端任务接口。只有显式 `VITE_ANALYSIS_MODE=demo` 才加载原 App / Store、模拟设施数据、定时 Loading 和 DemoMap fallback。

| 环境变量 | 用途与默认行为 |
| --- | --- |
| `VITE_ANALYSIS_MODE` | `api` 为正式入口；只有 `demo` 切换演示，未配置或其他值也进入 API |
| `VITE_API_BASE_URL` | 后端服务根地址，不包含 `/api/analyses`；未配置使用同源。本地分端口设为 `http://127.0.0.1:8000`；Vite 当前没有自动代理 |
| `VITE_ENABLE_DEVELOPER_MODE` | `true` 才显示本地开发者模式开关；仅控制 UI，不是权限边界，默认关闭 |
| `VITE_BAIDU_MAP_AK` | **浏览器类型** JavaScript 地图 AK，用于底图、定位、地点搜索和地址解析；缺少或加载失败时仍可输入坐标并分析 |
| 后端 `BAIDU_MAP_AK` | **服务端类型** AK，仅在后端配置，用于真实步行 Provider；不得放进任何 `VITE_*` 变量 |
| 后端 `ANALYSIS_PROVIDER` / `ANALYSIS_QPS` | 默认 Provider 为 `baidu`，真实模式要求服务端凭据和可行的正数 QPS；`synthetic` 使用离线时间场，不要求真实 AK |

浏览器 AK 与服务端 AK 是两个独立凭据，不能混用。前端本地配置位于 `.env.local`，后端本地配置位于 `backend/.env`，均不能入 Git。修改配置后重启相应服务。示例只允许占位符。

## 2. 当前实际调用的接口

| 方法 | 路径 | 请求体 | 成功响应 |
| --- | --- | --- | --- |
| POST | `/api/analyses` | 下节 JSON | 202，任务视图 |
| GET | `/api/analyses/{taskId}` | 无 | 200，任务视图 |
| GET | `/api/analyses/capabilities` | 无 | 200，三种模式的可用性与 OSM 元数据 |
| GET | `/api/analyses/{taskId}/result` | 无 | 200，分析结果 |
| POST | `/api/analyses/{taskId}/cancel` | 无 | 202，任务视图 |
| POST | `/api/analyses/by-request/{clientRequestId}/cancel` | 无 | 202，任务视图 |
| POST | `/api/analyses/{taskId}/routes/{facilityId}` | 无 | 200，`RouteEvidence` |

`by-request` 接口仅用于创建响应丢失后的恢复，不通过重新创建任务来取消。路径参数经过 URL 编码；请求 Content-Type 为 `application/json`。单次 HTTP 超时为 10 秒（路线请求 25 秒），轮询等待间隔为 1 秒（加上请求本身耗时）。

路线接口要求任务已 `completed` 且带 `facilityAnalysis`；同一设施的路线会缓存复用，每次分析最多 3 次新增路线查询。错误映射：409 设施结果尚未就绪；404 设施不属于本次分析或任务已过期；429 新增路线查询已达 3 次。路线端点与任务接口使用同一 `VITE_API_BASE_URL` 解析规则：未配置时同源请求，不硬编码端口。

`GET /health` 是手动诊断接口，业务页面不调用。`baidu_ak_configured: true` 仅表示凭据非空，不证明权限或真实请求成功。

`/api/v1/analysis/mock/{scenario}` 与 `/api/v1/analysis/synthetic` 是历史 N05 契约入口，具有 `analysis_id`、`schema_version`、`data`、`complete` 等不同字段。当前前端**不调用它们，也不将它们用作失败兜底**。

## 3. 创建任务 Request

| 字段 | JSON 类型 | 必填 | 约束与含义 |
| --- | --- | --- | --- |
| `center` | object | 是 | 分析中心；仅 `lng`、`lat` |
| `center.lng` | number | 是 | BD09LL 经度，−180～180；不能传数字字符串 |
| `center.lat` | number | 是 | BD09LL 纬度，严格大于 −85 且小于 85 |
| `coordinateSystem` | string | 是 | 固定 `bd09ll`；客户端显式追加 |
| `budget` | number（整数） | 后端可省，前端必传 | 200 / 400 / 800；后端默认 400；非完成百分比 |
| `analysisMode` | string | 开发者模式下传 | `baidu_online`、`osm_offline` 或 `hybrid`；省略时默认为百度在线 |
| `clientRequestId` | string | 是 | 1～100 字符，仅字母、数字、下划线、连字符；前端生成 UUID，用于幂等与取消恢复 |

```json
{
  "center": { "lng": 121.513926, "lat": 31.313077 },
  "coordinateSystem": "bd09ll",
  "budget": 400,
  "clientRequestId": "frontend-example-001"
}
```

不接受未知请求字段、布尔预算、非有限坐标或 WGS84 / GCJ02 / Demo 画布坐标。后端将中心归一化为六位小数。同一标识与相同中心/预算/分析模式复用原任务；同标识用于不同条件返回 409。丢失创建响应后的“重试”沿用原标识；已过期、失败或取消的任务重新分析时使用新标识。

## 4. 创建和轮询 Response

所有任务接口共用以下任务视图，前端校验这些字段：

| 字段 | JSON 类型 | 含义 |
| --- | --- | --- |
| `taskId` | 非空 string | 后端任务 ID；不是 `analysisId` 或 `analysis_id` |
| `status` | string | `running / cancelling / completed / cancelled / failed` |
| `stage` | string | 后端真实计算阶段或终态 |
| `requests` | 非负整数 number | Provider 调用计数 |
| `networkRequests` | 非负整数 number | 网络尝试预留计数；可能预留后取消，不能视为计费次数 |
| `budget` | number | 200 / 400 / 800 |
| `elapsedSeconds` | 非负 number | 后端任务耗时，单位秒 |
| `analysisMode` | string | `baidu_online`、`osm_offline` 或 `hybrid`；OSM 模式的请求计数不代表百度调用 |
| `dataSource` | string | `synthetic`、`baidu_walking`、`osm_offline` 或 `hybrid` |
| `error` | string 或 null | 任务错误；普通页面不直接显示此原始字段 |

| 状态/阶段 | 前端行为 |
| --- | --- |
| 创建请求未返回 | 立即显示“正在创建任务”，开始按钮 Loading 且禁用；控制器同步防止重复创建 |
| `running` | 轮询并展示真实阶段、计数和耗时 |
| `initializing / expanding / exploring / refining / reconstructing` | 初始化采样 / 检查并扩展范围 / 探索采样 / 边界细化与补测 / 重建时间场与几何 |
| 未识别的运行阶段 | 显示“正在计算等时圈”，不显示内部原文，不推测百分比 |
| `completed` | 进入前端本地 `fetching` 阶段：“正在整理结果”；读取并校验 result 后结束等待。`fetching` **不是后端 status** |
| `cancelling` | 显示“正在取消任务”，等待终态 |
| `cancelled` | 退出等待，明确显示取消；不读取新结果 |
| `failed` | 退出等待，提示执行失败并允许重试；不采用新结果 |

用户在创建响应返回前或读取结果期间取消，可立即停止本次等待并隔离迟到结果；尚在创建的请求返回任务 ID 后再取消服务器任务，界面说明这一差别。网络失败无法确认取消时保留恢复信息，重试确认后才能继续。

取消请求返回 202 不等于后台已停止；状态可暂时为 `cancelling`。服务器可能已完成任务，实际终态以响应为准。

## 5. Result Schema 与适配边界

`GET .../result` 仅在任务 `completed` 时返回 200；其他状态返回 409。完成只表示算法执行结束，不等于完整体检成功。

| 字段 | 类型 | 当前消费方式 |
| --- | --- | --- |
| `taskId` | string | 必须匹配当前任务 |
| `analysisMode` | `baidu_online / osm_offline / hybrid` | 必须与提交模式一致；旧响应缺失时按百度在线兼容 |
| `dataSource` | `synthetic / baidu_walking / osm_offline / hybrid` | 必须与任务来源一致；报告明确标识来源 |
| `provenance.osm` | object 或 null | OSM 参与时显示可用性、覆盖城市、数据日期、快照版本、署名、许可和限制 |
| `hybridResult` | object 或 null | 百度与 OSM 子结果及 `parallel_comparison` 策略；不直接合并几何 |
| `center` | `{lng:number,lat:number}` | 必须与提交中心归一化后相同；作为成功结果中心 |
| `generatedAt` | number | Unix 秒时间戳，显示分析时间 |
| `facilitiesStatus` | `not_integrated / complete / partial / failed` | `synthetic` 固定 `not_integrated`；真实 Provider 运行设施模块后为其余三值 |
| `facilityAnalysis` | object 或 null | 仅真实 Provider 设施模块运行时存在；结构见下节 |
| `data.facilities` | 数组或 null | 设施列表（id、名称、大类/小类、BD09LL 坐标、`in_circle` 三态）；`facilityAnalysis` 存在时必为数组 |
| `data.categories` | 数组 | 每小类 `query_status` 与 `count_in_circle`（可为 null），报告用“检索记录 · 估算圈内”展示 |
| `data.report` | string 或 null | 后端生成的业务报告文字，设施面板与报告第 2 节直接展示 |
| `isochrone.coordinateSystem` | `bd09ll` | 与几何坐标系一致 |
| `isochrone.geometry` | MultiPolygon 或 null | 已知可达区域；保留分量、孔洞、空集合与 null 的差异 |
| `isochrone.timeBands` | 数组（可选） | 5/10/15 分钟分层几何，`geometry` 可为 null；缺失时时间层选择回退整体等时圈 |
| `isochrone.unreachableRegion` | MultiPolygon 或 null（可选） | 不可达/未核验区域，独立图层 |
| `isochrone.unknownRegion` | MultiPolygon | 未知区域，缺少证据；不是不可达区或设施盲区 |
| `isochrone.uncertainRegion` | MultiPolygon | 尚需核实的边界区域 |
| `isochrone.computationExtent` | MultiPolygon | 计算范围，默认隐藏，可切换 |
| `isochrone.quality` | `usable / partial / insufficient` | 步行证据质量，不能当整份设施体检状态 |
| `isochrone.stopReason` / `warnings` | string / string[] | 停止原因与质量标记，例如 budget、deadline、range_unknown、unfinished_boundary |
| `isochrone.statistics` | object | 当前依赖 requests、network_requests、retries、unknown_area、unfinished_boundary、total_seconds、failures；未知面积单位平方米，页面换算平方公里 |
| `isochrone.config` | object | 依赖 origin、budget、seed；origin 为 `[lng,lat]`，与 center 一致，budget 必须匹配提交；算法阈值固定 900 秒 |

业务几何接受 `Polygon` 或 `MultiPolygon`；前端适配层会将 Polygon 归一化为 MultiPolygon 后交给地图。层级为多边形 → 环 → `[lng,lat]`，环必须闭合；第一个环为外环，后续为孔洞。

适配入口为 `src/analysis/adapter.ts`，运行时校验在 `validate.ts`；完整算法输出见 [算法 models.py](../../life-circle-algorithm/src/life_circle/models.py)，任务封装见 [后端 analyses.py](../../backend/app/analyses.py)。接口字段有变化时，先更新明确契约和适配测试，不能直接把响应当成 Demo 的 `AnalysisResult`。

## 6. partial / unavailable 与同一份结果

- 有效等时圈（包括有证据的空几何）且质量非 insufficient：允许保存并自动打开“部分体检结果”。即使算法 quality=usable，设施为有限检索也不称完整体检。
- `geometry=null` 或 `quality=insufficient`：体检为 unavailable，退出等待，显示证据不足；不自动打开新报告，不替换已有成功结果。
- `coordinates=[]` 是有证据的空几何；与 `null` 的“无法确定”含义不同。
- 无 `facilityAnalysis` 时三类设施数量及设施盲区数量保持 null，展示“无法确定”，不能显示 0，不能从未知区域推导设施盲区。有 `facilityAnalysis` 时数量来自后端 `count_in_circle`，标注“检索记录 · 估算圈内”；`serviceBlindRegions` 当前为空几何，设施服务盲区数量仍为“无法确定”。
- `lastResult` 是成功结果快照，供地图图层、设施面板、路线与报告共同使用。中心点或预算编辑后保留旧快照并标 stale；新有效结果才替换快照并清除 stale。失败、不可用和取消不会清空它。
- 地图将“已分析中心（与报告一致）”与“待分析选点”区分，图层说明标出报告中心。报告关闭后可重开。图层开关只影响显示，不修改报告或分析条件。路线查询绑定当前快照的 `taskId`，切换设施或结果时中止未完成请求并清空路线。

## 7. 错误与恢复

| 失败 | 普通用户提示与恢复 |
| --- | --- |
| 创建 POST 404 | 分析 API 地址或服务配置异常，请检查服务地址；不能称任务过期 |
| 已有任务的查询/结果 404 | 任务不存在或已过期，请重新分析 |
| 422 | 分析参数无效，请检查中心坐标和调用预算 |
| 503 | 分析服务当前不可用，请联系管理员检查步行服务配置 |
| 其他 5xx | 分析服务异常，请稍后重试 |
| 409 | 任务状态冲突，服务可能仍在运行其他分析，请稍后重试；前端不自动制造替代结果 |
| 网络、跨域或请求超时 | 无法连接分析服务或请求超时，请检查网络和服务地址后重试 |
| 非法 JSON/响应结构 | 后端返回格式异常，请检查服务版本 |
| 结果与提交中心、预算、来源或任务不符 | 拒绝结果，提示条件不一致 |

这些分支均退出等待、保留旧报告；HTTP 错误体、传输异常、堆栈与服务端凭据不直接展示。主动取消与网络故障分别处理。取消恢复里的 404 代表旧任务已不存在，可以清理恢复标识。

## 8. 当前能力边界及后端依赖

**已实现**（前端已消费、有测试覆盖）：

- 真实地图、点击/坐标选点、用户主动定位、POI 地点搜索与地址解析、任务链路、等时圈四类图层（可达/未知/不确定/范围）、不可达区域图层、5/10/15 分钟时间层（`timeBands`，缺失回退整体等时圈）、部分报告。
- 设施模块（真实 Provider 时后端返回）：设施列表与地图标记（最多 100 个）、大类筛选（购物/医疗/教育）、`in_circle` 三态展示、查询证据（页数/召回/状态）、采样点三态评估（有设施/查询内缺失/无法判断）、设施服务盲区图层（当前空几何）、中心到设施的步行路线（`RouteEvidence`，含距离/时长/端点核验与路径绘制）。
- POI 经百度浏览器 SDK 用于选中心；不作为圈内设施全集，不参与设施数量计算，不通过本任务接口返回。

**partial（已接入但证据有限）**：设施为有限范围关键词检索与采样点核验，`count_in_circle` 是“检索记录 · 估算圈内”，不等于全量目录或 1 公里步行覆盖；查询可能 truncated；未测点保持 unknown，不推断为盲区。

**limitation（保留字段，暂无证据）**：`serviceBlindRegions` 保留结构但返回空几何，不展示面积盲区结论。

**未实现**：全量设施目录、按类查询完整性保证、服务距离的面积级盲区评价、登录、持久化历史。`/api/v1/analysis/mock/*` 与 `/synthetic` 是历史 N05 契约验收入口，不作为任务 API 的备用数据源。

`synthetic` 是离线数学时间场，用于自动验收，无真实道路或真实设施。`baidu_walking` 使用真实路线证据，不自动回退 synthetic。main 已有国定一社区真实链路、限流修复、稳定性及算法比较记录，详见 [当前后端进度](../../backend/docs/当前进度与接口报告.md) 和 [comparison-v1 审计记录](../../backend/docs/comparison-v1_审计修复报告.md)；这不代表全部社区精度或完整设施体检已经验证。

任务存在当前进程内：每进程只允许一个运行任务，终态保留最多 30 分钟、20 条，服务重启后丢失。当前是本机联调服务，不具备任务持久化、跨进程调度或公网鉴权。

**仍待后端演进的业务需要（现有字段未覆盖）**：

- 每类设施查询的采集时间与完整性保证，用以区分“检索到的全部”与“截断后的部分”。
- 面积级服务盲区证据（当前 `serviceBlindRegions` 为空几何，前端只展示图层开关，不下结论）。
- 设施检索结果与任务快照之外的持久化组合方式。字段名称、端点、算法责任如有变化须由团队确认后再改前端契约。

## 9. 本地联调与自动验收

安装步骤以 [backend README](../../backend/README.md) 为准；需要已有锁定 Python 依赖和本地算法包。以下启动方式使用其中的现有环境，不读取或展示密钥内容。

后端终端（仓库根目录）：

```powershell
Set-Location D:\AI比赛project\Baidu-map\backend
$analysisPython = 'D:/CodexCaches/baidu-map-algorithm-venv/Scripts/python.exe'
$env:ANALYSIS_PROVIDER = 'synthetic'
& $analysisPython -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

前端本地 `.env.local` 示例（由开发者编辑，仅占位符）：

```dotenv
VITE_ANALYSIS_MODE=api
VITE_API_BASE_URL=http://127.0.0.1:8000
VITE_BAIDU_MAP_AK=<浏览器类型AK占位符>
```

前端终端：

```powershell
Set-Location D:\AI比赛project\Baidu-map\life-circle-demo
npm.cmd run dev
```

访问 `http://127.0.0.1:5173`；后端健康地址为 `http://127.0.0.1:8000/health`。默认 CORS 允许前端 5173 的 127.0.0.1 / localhost；更换端口需同步配置明确来源。不要同时运行多个后端 worker 或热重载来做任务验收。

自动测试：`npm.cmd test`、`npm.cmd run build`、`npm.cmd run test:analysis-ui`、`npm.cmd run test:integration`、`npm.cmd run test:e2e`。analysis-ui 为 HTTP/SDK 替身；integration 使用真实 FastAPI + synthetic Provider + SDK 替身，端口 5178/8018；demo 为原流程，端口 5173。测试不复用既有服务，端口需空闲。环境及产物目录覆盖方式见 [前端 README](../README.md)。

人工验收重点：真实底图/定位/POI；创建、轮询、整理结果与取消的视觉反馈；第一次成功后修改中心和预算、第二次失败/证据不足，地图与重开的旧报告仍一致且有 stale 提示；新成功结果统一替换。自动测试中的 synthetic 场景不能替代真实地图和社区业务验收。
